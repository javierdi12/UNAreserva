# Seguimiento 2 · Hito 2 - Concurrencia y Offline

## Tareas del hito

| # | Tarea | Descripción / criterio de cierre |
|---:|---|---|
| 1 | Indicador de pendiente de sincronizar y mensajes de conflicto | Mostrar claramente el estado de sincronización y los errores HTTP 409. |
| 2 | Vista de reservas del día y cancelación | Mostrar las reservas de hoy y permitir cancelarlas. |
| 3 | Pantalla de formulario de reserva conectada a la API | Permitir seleccionar recurso, fecha y franja, y enviar la reserva. |
| 4 | Aplicar reglas de conciliación | Marcar cada solicitud como aceptada, rechazada o en conflicto según el documento de reglas. |
| 5 | Endpoint o comando de sincronización de pendientes | Reenviar las solicitudes pendientes a la API al recuperar la conexión. |
| 6 | Detectar caída de MongoDB/Redis y guardar en SQLite | Registrar la solicitud como pendiente en SQLite cuando falle la conexión, en lugar de devolver un error. |
| 7 | Pruebas de reservas simultáneas sobre el mismo slot | Ejecutar solicitudes concurrentes y verificar que solo una reserva se confirme. |
| 8 | Respuesta 409 en conflicto y manejo de expiración del lock | Manejar slots bloqueados u ocupados y permitir la recuperación de locks expirados. |
| 9 | Integrar bloqueo Redis en `POST /reservas` | Adquirir el lock, validar en MongoDB, insertar la reserva y liberar el lock mediante `try/finally`. |
| 10 | Historial de cambios e índice único en MongoDB | Registrar creaciones y cancelaciones, y crear un índice único de recurso y franja como segunda barrera contra duplicados. |
| 11 | `GET /reservas/hoy` | Listar las reservas correspondientes al día actual. |
| 12 | `GET /disponibilidad` por recurso y fecha | Devolver las franjas libres y ocupadas de un recurso en una fecha determinada. |

## Evidencia de cierre

Cada tarea debe quedar respaldada por código o documentación versionada, pruebas
reproducibles, el Issue correspondiente actualizado y, cuando aplique, un Pull
Request revisado por otro integrante. Las pruebas offline deben demostrar que
la solicitud queda almacenada localmente y que puede sincronizarse al recuperar
MongoDB y Redis.
