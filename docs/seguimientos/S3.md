## Resultado esperado

El MVP integra MongoDB, Redis y SQLite. MongoDB conserva recursos y reservas,
Redis coordina el lock temporal y SQLite conserva solicitudes pendientes si
MongoDB o Redis no responden.

## Pruebas documentadas

Ejecutar desde la raíz del repositorio:

```text
python -m pytest -q
```

Los casos cubiertos son:

1. **Normal:** una reserva válida se confirma y la concurrencia no permite dos
   reservas para el mismo slot.
2. **Error de conexión:** si MongoDB o Redis falla, la respuesta queda en la
   cola SQLite con estado `pendiente`; al volver la conexión, se reintenta.
3. **Datos inválidos:** campos faltantes, fechas con formato incorrecto, rango
   invertido, horario fuera del recurso y conflictos devuelven el error HTTP
   correspondiente.

## Medición

```text
python scripts/benchmark_s3.py --repeticiones 5
python scripts/benchmark_disponibilidad.py <id-recurso> --repeticiones 5
python scripts/load_test_slot.py <id-recurso> --solicitudes 50
```

El primer comando reporta cinco ejecuciones por operación y la mediana en
milisegundos. Sus tres operaciones son:

| Operación | Qué demuestra | Medida reportada |
|---|---|---|
| `validar_rango` | Validación del caso normal | `mediana_ms` |
| `guardar_pendiente_sqlite` | Persistencia ante caída de un motor | `mediana_ms` |
| `sincronizar_pendiente` | Recuperación y conciliación | `mediana_ms` |

Para una evidencia final reproducible, guardar la salida del comando junto con
la fecha, versión de Python, número de ejecuciones y configuración; nunca
incluir credenciales. `benchmark_disponibilidad.py` y `load_test_slot.py`
complementan la medición local con disponibilidad y concurrencia sobre los
motores integrados.

## Manejo del fallo del motor secundario

Redis no es fuente de verdad. Si no responde durante una reserva, la aplicación
guarda la solicitud en SQLite y responde `202` con estado `pendiente`. Si Redis
falla al liberar el lock, el TTL permite su recuperación automática. Al
sincronizar, la aplicación vuelve a adquirir el lock y valida contra MongoDB;
una falla persistente deja la fila pendiente para otro intento.
